# 주식 수익 최대화 AI 고정 개발 원칙

주식 수익 최대화 AI는 단일 모델에 의존하지 않고, 통계 모델·머신러닝·딥러닝·강화학습을 단계적으로 검증하여 결합한다.

프로젝트의 최우선 목표는 매일 0.1% 수익을 보장하는 것이 아니라 다음 조건을 만족하는 것이다.

1. 수수료와 슬리피지를 반영한 후에도 양의 기대수익을 유지한다.
2. 특정 종목이나 특정 상승장에서만 작동하지 않는다.
3. 최대 낙폭과 일일 손실을 제한한다.
4. 단일 백테스트 결과보다 워크포워드와 모의매매 결과를 우선한다.
5. 복잡한 모델이 단순 전략보다 우수하지 않으면 사용하지 않는다.
6. 실거래 전 충분한 모의매매와 장애 테스트를 수행한다.
7. 미래 데이터 누수와 과적합을 엄격하게 차단한다.

# 확장된 개발 단계

## 1단계. 프로젝트 구조와 실행 환경

설정, 로그, 테스트, 모델 버전과 데이터 버전을 관리할 수 있는 기반을 만든다.

완료 조건:

- 실행 진입점이 명확하다.
- 비밀키와 생성 파일이 Git에 포함되지 않는다.
- 자동 테스트와 코드 품질 검사가 동작한다.
- 모델과 외부 API 연결부가 분리되어 있다.

## 2단계. 거래 목표와 위험 한도

시장, 시간봉, 보유 기간, 최대 보유 종목, 손절, 일일 손실과 최대 낙폭을 먼저 고정한다.

결정 항목:

- 거래 시장과 증권사
- 거래 대상 종목군
- 봉 주기와 의사결정 주기
- 예상 보유 기간
- 초기 자본과 추가 투입 규칙
- 종목별 최대 투자 비중
- 일일·주간 최대 손실
- 전체 최대 낙폭
- 손절·익절 규칙
- 거래 중지와 재개 조건

## 3단계. 데이터 수집

가격, 거래량, 시장지수, 변동성, 환율, 기업 정보, 공시와 뉴스 데이터를 수집한다.

모든 데이터에는 출처, 수집 시각, 시간대, 수정주가 여부와 버전을 기록한다.

## 4단계. 데이터 품질 관리

결측치, 중복, 이상치, 액면분할, 상장폐지 종목과 생존편향을 검사한다.

필수 검사:

- 시간 순서와 시간대 정합성
- 중복 봉과 누락 봉
- 0 또는 음수 가격
- 비정상 거래량
- 액면분할·배당·합병 반영
- 상장폐지 종목 포함 여부
- 미래 정보가 과거 행에 포함되는지 여부

## 5단계. 특징 생성

기술적 지표, 모멘텀, 변동성, 거래량, 시장 상대강도와 추세 상태를 생성한다.

특징은 반드시 해당 시점까지 공개된 정보만 사용하고, 학습·검증·실시간 환경에서 동일한 코드로 계산한다.

## 6단계. 단순 기준 모델

이동평균, 모멘텀, 평균회귀와 Logistic Regression을 기준선으로 사용한다.

단순 전략의 성과를 이기지 못하는 복잡한 모델은 채택하지 않는다.

## 7단계. 트리 기반 머신러닝

Random Forest, XGBoost, LightGBM과 CatBoost를 비교한다.

예측 대상을 분리하여 설계한다.

- 다음 기간 상승 확률
- 예상 수익률
- 예상 변동성
- 손실 발생 확률
- 거래하지 않아야 할 확률

정확도만 평가하지 않고 확률 보정, 정밀도, 재현율, ROC-AUC, PR-AUC와 실제 거래 성과를 함께 평가한다.

## 8단계. LSTM과 시계열 딥러닝

LSTM, GRU와 Temporal CNN을 적용한다.

시계열 입력 후보:

- 수익률
- 거래량 변화
- 변동성
- 시장지수
- 섹터 흐름
- 추세 상태
- 기존 모델의 예측값

LSTM은 단순 모델과 동일한 테스트 구간에서 비교하고, 성능 개선이 명확할 때만 채택한다.

## 9단계. Transformer 기반 시계열 모델

Temporal Fusion Transformer, PatchTST 등의 구조를 실험한다.

데이터가 충분하지 않거나 과적합이 발생하면 사용하지 않는다. 복잡하다는 이유만으로 채택하지 않는다.

## 10단계. 시장 국면 탐지

시장을 상승장, 하락장, 횡보장과 고변동성장으로 구분한다.

비교 방법:

- 이동평균과 변동성 규칙
- Hidden Markov Model
- 군집화
- 분류 모델

각 시장 국면에 맞춰 전략과 모델의 가중치를 다르게 적용한다.

## 11단계. 앙상블 AI

여러 모델의 결과를 결합한다.

예시 역할:

- 트리 모델: 단기 상승 확률
- LSTM: 시계열 추세
- 변동성 모델: 위험 예측
- 뉴스 모델: 감성 점수
- 국면 모델: 시장 상태

최종 결정은 단순 평균이 아니라 검증 성과에 따른 가중 평균이나 메타 모델로 수행한다.

## 12단계. 강화학습 환경 구축

강화학습은 바로 실거래에 적용하지 않는다.

환경 상태:

- 현금
- 보유 종목
- 평균 매입가
- 미실현 손익
- 시장 특징
- 예측 확률
- 변동성
- 최근 거래 기록

허용 행동:

- 매수
- 매도
- 유지
- 비중 축소
- 비중 확대

보상 함수:

- 순수익
- 수수료
- 슬리피지
- 최대 낙폭 패널티
- 과도한 거래 패널티
- 변동성 패널티
- 집중투자 패널티

강화학습 환경은 주문 지연, 체결 실패와 거래 가능 수량을 현실적으로 반영해야 한다.

## 13단계. Offline Reinforcement Learning

실시간 시장에서 직접 탐험하지 않고 과거 데이터와 모의매매 기록으로 학습한다.

후보 방식:

- Conservative Q-Learning
- Implicit Q-Learning
- Decision Transformer
- 제한된 환경의 PPO

강화학습 모델은 수익률뿐 아니라 최대 낙폭, 거래비용과 안정성도 동시에 개선해야 채택한다.

## 14단계. 워크포워드 검증

과거 전체 데이터를 한 번에 학습하지 않는다.

반복 구조:

`학습 기간 → 검증 기간 → 테스트 기간 → 시간 이동 → 재학습`

각 구간에서 모델과 하이퍼파라미터를 다시 검증하고, 테스트 구간의 정보는 모델 선택에 사용하지 않는다.

## 15단계. 과적합 방지

필수 검사:

- 미래 데이터 누수
- 생존편향
- 데이터 스누핑
- 과도한 하이퍼파라미터 튜닝
- 특정 종목 의존
- 특정 기간 의존
- 수수료 미반영
- 장중 체결 가능성 오류

추가로 Purged Cross Validation, Embargo와 확률 보정을 필요에 따라 적용한다.

## 16단계. 스트레스 테스트

다음 조건에서도 전략을 재검증한다.

- 수수료 2배
- 슬리피지 2~5배
- 주문 일부 미체결
- 데이터 지연
- 서버 재시작
- API 오류
- 급락장
- 거래정지
- 유동성 감소

스트레스 조건에서 손실 제한이나 거래 중지가 작동하지 않으면 다음 단계로 진행하지 않는다.

## 17단계. 위험관리 AI

예측 모델과 주문 모델을 분리한다. 위험관리 엔진은 AI의 매수 신호를 거부할 수 있어야 한다.

필수 제한:

- 종목별 최대 비중
- 일일 최대 손실
- 주간 최대 손실
- 연속 손실 제한
- 최대 낙폭 제한
- 변동성 기반 주문 크기
- 비상 거래 중지
- 중복 주문 차단

위험관리 규칙은 학습 모델보다 높은 우선순위를 가진다.

## 18단계. 모의매매

실시간 시장 데이터로 최소 8주 이상 운영한다.

확인 항목:

- 예측값과 실제 체결 결과
- 백테스트와 실시간 결과 차이
- 주문 누락과 중복
- 장시간 실행 안정성
- 모델 재학습 안정성
- 손실 제한 작동 여부

## 19단계. 챔피언-도전자 구조

현재 운영 모델을 챔피언으로 유지하고 새 모델은 도전자로 테스트한다.

도전자 모델이 충분한 기간 동안 다음을 모두 개선할 때만 교체한다.

- 순수익
- 최대 낙폭
- 샤프지수
- 거래비용
- 안정성
- 시장 국면별 성과

모델 교체 후 문제가 발생하면 즉시 이전 챔피언으로 복구할 수 있어야 한다.

## 20단계. 소액 실거래

모의매매를 통과한 뒤 최소 금액으로 시작한다.

실거래 초기에는 강화학습 모델이 주문을 직접 결정하지 않고 기존 전략의 결정을 보조하거나 비중을 조절하는 역할부터 수행한다.

실거래 확대는 기간이 아니라 누적 거래 수, 위험 한도 준수율과 모의매매 대비 오차를 기준으로 결정한다.

# 최종 모델 구조

```text
데이터 품질 검사
→ 시장 국면 탐지
→ 트리 모델 예측
→ LSTM·Transformer 시계열 예측
→ 뉴스 감성 분석
→ 앙상블 판단
→ 강화학습 비중 조절
→ 위험관리 승인
→ 모의 또는 실제 주문
→ 성과 기록과 재학습
```

하나의 거대한 AI가 모든 결정을 수행하지 않는다. 예측, 비중 결정, 위험관리와 주문 실행을 분리해 각 부분을 독립적으로 검증한다.

# 모델 채택 기준

새 모델은 다음 조건을 모두 만족할 때만 실제 시스템에 포함한다.

- 테스트 구간에서 기준 전략보다 우수하다.
- 워크포워드 결과가 안정적이다.
- 수수료와 슬리피지를 반영한 후에도 양의 기대수익을 보인다.
- 최대 낙폭이 허용 범위 이내다.
- 여러 시장 국면에서 작동한다.
- 모의매매 결과가 백테스트와 크게 다르지 않다.
- 오류 발생 시 안전하게 중단할 수 있다.
- 결과가 통계적으로 우연일 가능성을 별도로 검토한다.

복잡한 AI가 단순 모델보다 성과가 낮거나 불안정하면 단순 모델을 사용한다.

# 설치

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
cp .env.example .env             # Windows: copy .env.example .env
```

# 현재 지원 명령

```bash
python main.py download --symbol AAPL --start 2018-01-01 --end 2026-01-01 --output aapl.csv
python main.py train --data aapl.csv --model model.joblib
python main.py predict --data aapl.csv --model model.joblib
python main.py backtest --data aapl.csv --model model.joblib
ruff check .
pytest -q
```

# 실제 증권사 연결 원칙

`connectors.py`의 `Broker` 규격을 구현하되 18단계 완료 전에는 실주문을 활성화하지 않는다.

```python
class MyBroker:
    def get_cash(self) -> float: ...
    def get_position(self, symbol: str) -> float: ...
    def buy(self, symbol: str, quantity: float) -> str: ...
    def sell(self, symbol: str, quantity: float) -> str: ...
```

투자 손실 가능성이 있으며 모델 출력은 투자 수익을 보장하지 않습니다.
